# Встреча 17

## Что исправили

- Привели `application/benchmark/metrics/collector.py` к новой логике после merge.
- Убрали конфликт между старым подходом `PerformanceMetrics/record_latency` и новой логикой `LatencyStats`.
- Оставили схему:
  - `start_run()` запускает фоновые CPU/GPU collectors на весь прогон модели;
  - `stop_run()` останавливает фоновые collectors после прогона;
  - `mark_start()` фиксирует старт одного inference;
  - `mark_stop()` фиксирует конец одного inference и добавляет latency в историю.

## Почему оставили LatencyStats

- `LatencyStats` сразу дает агрегированные значения по latency:
  - `fps`;
  - `mean_ms`;
  - `p50_ms`;
  - `p95_ms`;
  - `p99_ms`;
  - `min_ms`;
  - `max_ms`.
- Это удобнее для отчетов, чем хранить только длинную историю latency/FPS.
- `BenchmarkResult.performance` и `ModelBenchmarkResult.performance` теперь используют `LatencyStats | None`.

## Что убрали

- Убрали локальные остатки старой логики:
  - `PerformanceMetrics`;
  - `record_latency()`;
  - `self.performance = PerformanceMetrics(...)`;
  - лишние закомментированные строки в `application/benchmark/runner.py`.

## Корректная схема прогона

```python
collector.start_run()

try:
    for frame in images:
        collector.mark_start()
        try:
            model.predict(frame)
        finally:
            collector.mark_stop()
finally:
    collector.stop_run()

result = collector.get()
```

## Что это дает

- CPU/GPU метрики собираются за весь прогон модели, а не за один кадр.
- Latency измеряется отдельно для каждого inference.
- FPS считается из средней latency внутри `LatencyStats`.
- В отчет попадает компактная статистика вместо большого списка сырых значений.
